# 旧 Web 服务访问边界

根目录 `npm start` / `start.command` 继续提供旧工作台。服务固定监听 IPv4
`127.0.0.1`，支持当前端口的 `localhost` 与 `127.0.0.1` Host；不提供 LAN
访问。`PORT` 可指定端口，`APP_ORIGIN` 不再改变信任边界。

仅 `/`、`/index.html` 是静态入口，页面所需脚本和样式均内联。整个仓库、
`/config.json`、扩展源码及隐藏文件不再通过静态服务暴露；扩展应按现有方式
加载安装包内资源。入口和配置读取拒绝符号链接及非普通文件。

`GET /api/config` 保留，供旧页面、CLI、Chrome 扩展后台及扩展页面读取。
Chrome 扩展 Origin 只允许读取此端点，不能获取写入令牌。无 CORS 授权，
普通跨站页面不能读取配置；扩展使用现有 host_permissions。内容脚本不应
依赖跨站直接读取，应经扩展后台访问。无 Origin 的本机程序仍可读取配置。

写入继续支持旧页面和 CLI：先同源 `GET /api/session` 获取本进程随机令牌，
再以 `X-FlowHub-Token` 和 `Content-Type: application/json` POST 到
`/api/config`。旧页面和 CLI 已接入。外部脚本需采用此协议，跨站 Origin
与跨站 Fetch Metadata 均被拒绝。令牌不持久化，重启后失效。本机程序可
获取令牌，故这不是对恶意本机进程或其他本机用户的隔离。

配置请求及格式化后内容均限 1 MiB，保留现有 `items` 数组校验，不改变
数据契约。只允许一个在途写入，竞争请求返回 429。写入先创建独占、权限
0600 的临时文件并同步，随后同目录 rename 原子替换；不会沿配置符号链接
写入目标。失败返回通用错误，临时文件清理。rename 提供原子可见性，不承诺
突然断电后的目录持久性，也不协调其他本机编辑器的并发写入。

`GET /api/probe` 保留兼容响应，但固定返回 `status: disabled`，不解析、
请求目标或跟随重定向。旧页面仍尝试 iframe 嵌入，由浏览器执行目标的
X-Frame-Options/CSP 策略；不再提前给出响应头诊断、重定向后地址或可嵌入
保证。被浏览器拒绝的页面可用“跳转打开”。无需任何服务器出站探测并发。

请求头上限 8 KiB、请求处理期限 5 秒、空闲连接超时 5 秒、最多 32 个连接
及 16 个在途处理，响应关闭连接。超量请求返回 503 或连接拒绝，超时关闭
连接（可返回 408）；畸形 URL 返回 400，不结束进程。这个服务面向低流量
本机工作台，不提供公网服务或抵御同机恶意进程持续耗尽资源的保证。

验证：根目录 `npm test`。测试复制服务和页面到系统临时目录，只写 fixture
配置；覆盖入口、CLI、扩展读取、来源与令牌、源码/隐藏文件/路径穿越/
符号链接、畸形 URL、大小/中断/慢请求/竞争写入、原子替换及本地重定向
fixture 零出站请求。另按项目要求执行 `cd app && npm test`。
