# 应用目录监听与索引更新

`app/src-tauri/src/application_index.rs` 管理应用目录快照、持久化缓存和后台监听。启动时先读取 `application-index.json`，单个后台线程注册原生目录监听后再检查磁盘。macOS 使用 notify 的 FSEvents 后端，空闲时阻塞等待通知，不定时轮询全盘。

- `/Applications`、`~/Applications`、`/System/Applications` 支持子文件夹；发现 `.app` 后停止向包内递归，不跟随普通目录符号链接，也不扫描隐藏的安装暂存目录。
- `/System/Library/CoreServices` 只扫描本层，其 `Applications` 单独扫描，避免遍历系统框架和资源树。尚不存在的应用目录通过父目录监听，创建后补上递归监听。
- 连续变动合并到静默 1 秒后处理，持续变动最多等待 5 秒。容量为 1 的唤醒通道配合共享待办状态，不会因安装事件洪峰积压无界消息，也不会丢掉扫描期间到达的新变动。
- 通知只触发后台目录快照比较，路径、包和 Info.plist 的时间／大小没有变化时，不重新读取应用名称，也不重写索引。明确的 Info.plist／本地化名称变更和系统要求重扫的事件会强制刷新元数据，兼容保留时间戳的安装器。读取目录失败时保留上一份可用缓存。
- 安装事件后依次延迟 2、8、20 秒复查，覆盖应用目录先出现、Info.plist 后复制完成的情况；完成后停止计时。通知丢失或监听建立失败时，唤起和搜索会请求后台兜底检查，请求间隔至少 30 秒。间隔使用墙钟时间，休眠恢复不会因 uptime 停滞而继续跳过检查。
- 唤起和搜索路径只操作内存中的待办状态并尝试唤醒线程，不执行目录遍历；空索引也交给后台填充，完成后推送更新通知。

索引更新发送 `flowhub:applications-updated`。适配层清理图标缓存，搜索控制器同时更新空查询缓存和当前应用搜索结果。其他搜索范围不被切换；旧查询／旧通知的异步响应不能覆盖新结果。后台更新保留当前输入、仍存在的键盘选中对象和滚动位置，IPC 暂时失败时保留内容并在下次唤起重试。原索引缓存格式兼容，目录快照增加规则版本前缀以触发一次重建。

验证入口：Rust 的 `application_index::tests` 包含原生目录事件、安装完成／移动／删除、子目录、符号链接、防抖与节流测试；`app/scripts/tests/application-index.test.cjs` 通过真实搜索控制器验证实时更新、跨范围缓存、旧响应竞争、键盘导航及失败恢复，并纳入 `pnpm test`。
