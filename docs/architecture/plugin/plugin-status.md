# 插件状态组件

插件 manifest 声明 `statusSurface: true` 后，可提供只读 `status_snapshot` RPC。宿主每 15 秒读取摘要，不提交采集或远程命令。摘要格式为 `{title, monitoring, rows:[{id,name,status,at,values:{cpu,memory,disk}}]}`；status 为 healthy/error/stale/unknown，at 为采集时间毫秒值。不得包含密码、私钥、SSH 参数或原始命令输出。

FlowHub 提供独立菜单栏状态下拉与可拖动、置顶的桌面监控窗。窗口的显示配置由宿主 `plugin-status.json` 保存，菜单栏关注项按机器 ID 筛选，未选则显示全部；插件停用或卸载后移除窗口和菜单栏入口。菜单栏最多显示 12 项，其余在监控窗查看。关闭窗口后可从机器页「桌面与菜单栏」重开。正在显示的窗口可随 FlowHub 下次启动恢复；位置在关闭时保存，已移除显示器上的位置会回到主屏。

机器插件按采集间隔的三倍判断数据过期；没有数据为未采集，采集失败为异常，不将这两种情况称为离线。重启后的内存采集缓存为空时显示未采集。

## 监控窗概览与筛选

监控窗顶层分为“状态”和“显示设置”两个标签，支持方向键、Home/End 切换。状态页默认概览最多显示 5 台，初次依次优先异常、过期、未采集、已关注及其他正常机器；正常机器也可补足概览。“全部”显示完整列表，“关注”只显示已保存关注项，没有关注时明确提示设置，不默认为全量。摘要计数基于当前范围、状态过滤与概览截断之前的机器；点击状态按钮过滤，再次点击或选择全部状态可清除。概览的“查看全部”进入全量列表并清除状态过滤。显示设置独立展示菜单栏、置顶与关注项；切换标签保留筛选、展开及未保存草稿，后台轮询继续遵守保存竞态保护。演示模式可查看显示设置，所有写操作仍禁用。

周期刷新保留各范围现有机器 ID 的相对顺序，新增 ID 追加，删除 ID 清除；状态变化不会自动重排已存在的行。主动切换范围重新按优先级建序。展开状态按 ID 保存，刷新保留原行 DOM 和焦点；对象被移除后清理其展开状态。

折叠行展示名称、插件声明的状态、一项有效关键指标和相对采集时间；展开显示 CPU、内存、磁盘及完整采集时间。未知状态归为未采集，不根据指标推断健康；缺失或非有限指标显示 `—`。无效和未来时间有明确标记，不显示为刚刚更新。等待首次缓存、没有机器、没有关注、筛选无结果、读取失败、采集异常及采集未启用分别提示，读取失败保留上次缓存；过期状态以插件声明为准。

浏览器打开 `plugin-status.html?preview=demo` 可使用内置只读演示，无需额外服务，包含 8 台机器、全部四种状态、关注和缺失指标。范围、筛选和展开可操作，保存、菜单栏和打开插件禁用，不注入原生能力或发起采集。普通浏览器入口仍提示从 FlowHub 打开；真实原生窗口忽略 demo 参数，保持真实数据。菜单栏、置顶及关注保存仍使用原有 `plugin_status_api` 协议。

## 原生 WidgetKit 扩展

当前实现是独立桌面监控窗口，不是 macOS 小组件图库中的 WidgetKit 扩展。当前环境只有 Command Line Tools，没有完整 Xcode、Widget 扩展 target 和用于 App Group 的团队签名配置。原生小组件需要单独的 Swift/WidgetKit 扩展、App Group 共享摘要文件、签名与宿主打包流程，并受系统刷新预算限制；不能通过 Tauri 页面模拟注册进小组件图库。后续扩展应复用这里的无凭据状态摘要，不直接访问插件密码数据库。
