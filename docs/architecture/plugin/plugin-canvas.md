# 桌面组件画布与插件页面

FlowHub 管理透明窗口、卡片位置与尺寸、置顶、右键菜单、插件选择和窗口生命周期。卡片内容、业务编辑器、详情与历史曲线由插件包中的 HTML/CSS/JS 提供。机器指标名称、单位、图表及查询逻辑不再放在宿主中。

点击卡片打开独立详情窗口，右键编辑或移除，Enter 打开、Shift+F10 打开菜单。拖动卡片调整位置，边角手柄自由缩放；松手后自动靠拢，间距 10 px。布局和插件配置保存在 `plugin-canvas.json`。旧布局的 `view`、`row`、`metrics` 会作为初始配置交给插件，原有尺寸和坐标保留。编辑保存后使用通用 `config` 对象。

仅查看模式锁定拖动、左键操作、编辑和移除，保留右键及 Shift+F10 菜单。菜单可显式打开详情、进入设置或退出仅查看状态；空画布也能右键退出。顶部工具栏仍隐藏，插件 iframe 不接收输入。

macOS 完整画布移动时在主线程读取 AppKit 窗口左上角，保存为 `windowPositionAppKit`（全局 AppKit 点坐标，Y 向上）；紧凑模式及模式过渡不覆盖该位置。首次迁移到呈现存储时，先通过 AppKit 恢复旧位置，再采样为完整画布的显示器几何，最后显示窗口；已有 `canvas-presentation.json` 几何时优先使用其中对应模式的记录。旧位置校验使用 `NSScreen.frame` 的点坐标，避免 MacBook 2x 与扩展屏 1x 混用物理像素导致跨屏偏移。旧 `windowPosition` 按目标屏幕缩放比例迁移；其他平台继续保存原生物理坐标。原显示器已断开或位置不可见时迁移到可见区域。前端保存布局时保留原生拥有的 `viewOnly`、`desktop` 和最新窗口位置，避免旧快照覆盖新位置。

## 插件声明

在 `flowhub-plugin.json` 中声明：

```json
{
  "statusSurface": true,
  "widget": {
    "card": "widget-card.html",
    "editor": "widget-editor.html",
    "detail": "widget-detail.html"
  }
}
```

入口路径相对于主 UI 页面的目录，必须指向包内 HTML，拒绝目录穿越和越界符号链接。组件列表发现所有已启用且声明 `widget` 的插件，不要求 `statusSurface`；后者只用于可选的状态缓存和菜单栏监控。添加时先选择插件，再加载该插件的配置页面。没有声明的旧插件保留已有布局并提示升级。新增文件随插件包发布；此次需升级一次宿主，以后修改机器卡片、指标配置或曲线只需发布机器插件。

## 页面通信

宿主以 `sandbox="allow-scripts"` iframe 加载插件页面，不开放同源访问、弹窗、表单提交或宿主 IPC。默认卡片 iframe 仅展示内容，由宿主处理点击和拖动；编辑器和详情 iframe 可交互。

需要在卡片内操作时，插件可在 `widget` 中声明 `interactive: true`。宿主为此类卡片保留顶部 24px 拖动/右键编辑区域，iframe 接收其余区域的鼠标和键盘事件。默认尺寸为 384×360，已有小卡片至少扩至 320×280，列表可在卡片内滚动。普通机器卡片保持原有行为。

状态更新通过已有 iframe 的 `flowhub:widget-init` 传入新上下文，不因定时刷新重新加载页面，避免打断输入、确认框和执行中的 RPC；布局或插件页面定义变化时才重新挂载。插件应在执行操作期间保留确认的目标，不用新快照替换用户正在确认的内容。

`widget-frame.js` 与插件自己的 `widget-bridge.js` 使用 postMessage 通信。每次挂载生成随机 token，通过 URL fragment 传给页面；双方同时验证消息窗口和 token，避免切换来源后旧页面继续调用接口。

- `flowhub:widget-ready` / `flowhub:widget-init`：传递 `{config,title,snapshot,preview}`。
- `flowhub:widget-size`：编辑页可报告内容 `height`（有限正数，最多 2000 CSS 像素）；宿主验证来源和 token 后调整编辑 iframe，高度变化只影响编辑区。表单使用单层滚动，保存按钮固定在对话框底部。
- `flowhub:widget-save` / `flowhub:widget-config`：请求校验并保存插件配置，错误显示在宿主编辑器中。配置必须是最多 64 KiB 的对象。
- `flowhub:widget-rpc` / `flowhub:widget-result`：宿主将请求送至绑定插件的固定 `widget_api` 方法，页面不能指定其他插件或其他 RPC 方法。详情窗口在原生侧也绑定插件身份，关闭后移除绑定。

插件决定 `widget_api` 的动作语义。机器插件目前只开放 `history`，读取本地 SQLite，返回 `{data,unit}`；不开放命令执行或配置写入。图表缺失采样保留空档。Docker 插件另外提供停止目标预览和显式确认接口，重新校验本机环境及容器集合，并逐个核实停止结果；宿主不解释 Docker 命令。

## 状态与预览

宿主每 15 秒读取插件已有 `status_snapshot` 缓存，不额外启动远程采集。状态行的 `summary` 由插件格式化，供原生菜单栏使用；宿主仅处理通用状态和名称。`values` 的意义及渲染由插件决定。

浏览器使用 `plugin-canvas.html?preview=http://127.0.0.1:5182/`，从该插件的 `widget-preview.json` 加载页面定义和模拟状态，布局只保存在 localStorage，不调用原生功能。预览数据也属于插件。
# 对象详情导航

交互式组件可向宿主发送 `flowhub:widget-navigate`，指定 `action: "detail"` 和可选对象 `selection`（JSON 对象，最多 4096 字符）。宿主核对 iframe 来源与令牌，将选择放入详情配置的 `config.selection`；插件 ID 仍由宿主绑定，不接受消息覆盖。`action: "editor"` 打开当前组件编辑器。Docker 用此传递容器 ID、Compose 项目或镜像页面及 Docker context，详情页核对当前环境后定位对象。

## 锁定布局与仅查看

`layoutLocked` 与 `viewOnly` 独立持久化；历史文件缺少字段时默认为 `false`。锁定布局禁止卡片移动、缩放、增删及配置编辑，也禁止新建、重命名、删除布局。布局切换、置顶、详情导航和交互式插件的内部操作及认证 RPC 仍可使用；插件请求 `editor` 导航也受锁定约束。窗口本身仍可移动。原有仅查看模式继续隐藏工具栏、禁用左键和拖动，右键菜单及设置页可退出；退出仅查看不会解除布局锁定。

画布与设置页通过 `setLayoutLocked` 和 `flowhub:canvas-layout-locked` 同步；两种模式切换都取消未完成的卡片手势、编辑弹窗与菜单。设置失败保留原模式；异步读取或旧请求完成不能覆盖期间收到的更新事件。浏览器画布可在 localStorage 验证锁定与解锁，不启用原生功能或插件 RPC，浏览器设置页保持只读。

原生保存保留当前 `layoutLocked`、`viewOnly`、桌面显示状态和窗口位置。锁定时完整布局快照若改动任何 board/card 内容会被拒绝，包括排队中的旧编辑；锁定下切换布局或置顶使用仅包含 `active`、`pinned` 的保存负载，原子校验字段及目标布局，不写回前端补齐的历史尺寸和坐标。插件打开画布时的自动加卡也在同一原生状态更新中检查模式，不能绕过锁定或覆盖新模式。

## 详情复用与返回

只有插件声明 `widget.detail` 时，组件点击、Enter 和右键菜单才提供详情入口；插件内 `detail` 导航也遵守同一支持检查。名称、状态和指标不额外挂载插件未声明的导航动作。画布等待自己的保存队列后发送 `boardId`、`cardId`、插件 ID、配置和标题，原生核对布局内组件归属。

详情身份由布局、组件、插件及具体 `config.selection` 组成；递归排序 selection 对象键，数组保留顺序。相同对象更新普通配置、标题及快照时复用原窗口，不同对象分窗。原生登记创建预约并唤醒并发请求，创建失败和窗口销毁清除身份登记；详情 RPC 始终绑定登记插件。每次上下文更新递增 revision，页面收到通知后重新读取；旧异步读取不能覆盖新版本。同插件及页面版本保留 iframe，仅通过安全桥 `updateContext` 更新数据，插件升级导致页面 URL 改变时才重新挂载。

详情页“返回画布”恢复来源布局、选中并聚焦来源组件，再关闭详情；“关闭详情”只关闭当前详情。两种命令及上下文读取仅允许登记的详情窗口调用。来源已移除或更换插件时安全返回当前画布，不选择同 ID 的其他插件。返回通过 URL、窗口事件及原生 get 的待恢复目标覆盖画布尚未加载的情况；各通道携带原插件和同一次返回的唯一 `requestId`，画布去重已处理目标，防止后续轮询重放旧返回覆盖用户的布局切换，也核对本地未保存的插件替换。不解除锁定或仅查看模式，不改写卡片配置和几何。

浏览器详情仍为只读：返回地址限定为同源同目录的 `plugin-canvas.html`，保留原查询及来源标识，恢复布局与选中项；预览资源限定 HTTP(S) 当前服务目录，不启用原生或插件 RPC。详情打开失败或十秒未就绪提供重试及返回入口，重试销毁旧安全桥；返回失败保留详情并可重试。原生焦点、Space 及多屏行为仍需实机验收。
## 紧凑常驻入口

完整画布与紧凑状态条复用 `plugin-canvas` 窗口和原有权限。首次默认关闭，可在画布“更多 → 紧凑状态条”启用并选择关注组件；关注以 `{boardId, cardId}` 标识，跨布局同名卡片不会混淆，删除后的无效关注不显示。点击“收起”或“展开画布”切换，不响应悬浮自动展开。锁定布局和仅查看模式不因切换改变；仅查看模式也保留独立的展开/收起入口。打开详情后返回画布恢复完整呈现，以便看到来源卡片。

`canvas-presentation.json` 独立保存 `enabled`、`collapsed`、`favorites`、递增 `revision` 及各显示器上两种呈现的位置尺寸。旧布局文件、完整布局保存及锁定时的精简保存均不覆盖这些原生拥有的字段。`get` 将 `presentation` 与 `layout` 并列返回；`configureCompact` 允许设置与画布来源配置，`setCompact`、`snapCompact`、`compactMenu` 仅允许画布调用。前端按 revision 忽略陈旧轮询和确认，并在切换时取消未完成拖动、编辑器与布局菜单；调用失败保留原呈现并显示可重试错误。

紧凑条显示关注名称首字头像和现有缓存的状态，不发起新采集或插件 RPC。`cardConfig.row` 对应 `source.snapshot.rows[].id`；明确的 `snapshot.error` 显示读取异常，无对应行、未提供统一状态的组件或不可用插件显示未采集/无状态/插件不可用，未知状态不会推断为正常，缺失或非有限指标不填零。关注区支持横向滚动与键盘聚焦。低频原生操作位于“更多”菜单：置顶沿用布局 `pinned`，贴边使用当前显示器可用区域，隐藏只影响当前窗口、保留常驻设置；可从设置的“打开桌面组件”恢复，应用重启仍按原常驻设置恢复。

原生分别记录完整与紧凑几何，按显示器稳定身份保存，恢复时按当前缩放与可用区域限制尺寸和位置；显示器断开后选择仍连接的显示器并限制到可见区域。macOS 优先使用显示器 UUID，镜像屏无法唯一匹配或其他平台没有稳定标识时，退回名称与同名序号，此时相同型号显示器重新插拔可能交换记忆位置。模式过渡期间不记录临时窗口事件，旧 Moved/Resized 事件不能将完整尺寸写入紧凑位置。多屏、缩放、全屏和 Space 行为仍需真实原生验收，纯几何测试不能替代该验收。

macOS 通过显示器重配置通知主动检查运行中的画布：配置完成后在主线程恢复完全不与任何可用区域相交的窗口；仍有交集的正常拖动不强制吸回。窗口销毁时注销监听，迟到回调不能影响新窗口。其他平台目前在重新打开时纠正离屏位置。`get.windowGeometryRestored` 标识本次打开已恢复持久完整尺寸，前端仅跳过首次内容自动适配，后续实际内容尺寸变化仍可适配；初始读取完成前不调整窗口，避免覆盖原生恢复的尺寸。

浏览器显式 `plugin-canvas.html?preview=demo` 使用本地只读样例，完整模式也有可见状态卡片，无插件 iframe、外链请求或伪造原生桥；呈现及关注设置仅保存在内存，不写布局或用户配置。原生环境忽略 demo 参数。普通浏览器预览保持既有权限边界，紧凑呈现配置也只在本次页面生效。

## 呈现可见性与生命周期

`plugin-canvas` 的 `get` 附带 `{active, revision}` 生命周期快照，原生通过 `flowhub:canvas-lifecycle` 发布同一序列的更新；专用 `lifecycle` 读取只允许画布窗口，用于页面恢复时补查错过的通知。设置页、详情和插件 iframe 不能写入或冒充窗口可见性。窗口会话销毁清理监听并使旧 epoch 失效，重建继续递增 revision，迟到事件不会污染新窗口。

macOS 使用 `NSWindow.isVisible`、最小化标记和 `occlusionState`，监听该窗口的遮挡/最小化/恢复通知；不把失焦、浏览器 `document.hidden` 或其他窗口的状态替代桌面画布可见性。未知状态继续刷新。其他平台缺少统一遮挡通知，每秒串行读取可见/最小化标记；只在窗口会话存在时运行，不访问插件缓存或 RPC，不积压主线程采样。macOS 不增加此计时器。

宿主不可呈现时停止 15 秒缓存读取和 150ms cursor 轮询，卸载卡片 iframe 并销毁安全桥；已经执行中的插件 RPC 不承诺取消，但销毁后的桥不会回传迟到结果。紧凑模式继续读取缓存以更新关注状态，停止不再用于画布菜单/悬浮的 cursor 轮询。原生 `status.rs` 的全局采集供托盘及其他消费者使用，保持原有生命周期；减少宿主读取不表示减少后台采集。

重新可见后先取最新缓存，再挂载卡片。请求绑定生命周期世代，恢复前的旧请求和旧 revision 无法重放；缓存读取失败保留已保存布局并提供明确重试，不用空 sources 归一化覆盖卡片。原生窗口可见但 `document.hidden=true` 时仍继续刷新。浏览器只读预览依照页面可见性暂停/恢复，不启用原生能力。

隐藏和指针离开只关闭临时菜单，编辑器、命名与确认弹窗由用户显式完成/取消关闭；编辑期间固定源插件版本和 iframe，后台插件更新/移除显示提示，用户取消后重开才使用新版，避免恢复刷新重置未保存草稿。编辑器内的插件定时器及在飞保存保留，本轮不改变其业务 RPC。卡片及编辑器快照更新分别处理，恢复缓存不向编辑器再次发送初始化消息。减少动态效果规则限定画布及其 portal，覆盖短过渡但不移除焦点与交互。
