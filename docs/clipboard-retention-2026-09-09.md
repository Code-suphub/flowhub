# 剪贴板周期留存与容量边界

配置位于 `plugins.clipboard.settings`：`retentionDays` 默认 30，0 无期限；新增 `maxRecords`、`maxBytes` 缺省/0 都不限制，旧用户不会自动启用容量淘汰。

启用插件后，writer 启动即检查，此后每 60 秒检查。队列持续非空也会检查；最多每批删除 256 条，积压时一秒后继续。配置保存先停止监听、排空并 join writer，再执行存储事务；成功或恢复后以对应配置重新启动。停用暂停后台清理，退出请求排空 writer。搜索独立过滤超过期限的记录（精确到 SQLite julianday；恰好边界保留）。

淘汰按最近复制时间从旧到新，同时间按 ID 从小到大。容量计算保留最新前缀；最新单条超过字节上限时，该条及旧记录最终全部淘汰。逻辑字节统计 UTF-8 文本、PNG 的记录 size、文件路径 JSON 的 UTF-8 字节，不计引用原文件大小、索引、空闲页或 WAL。容量不是磁盘硬配额，清理不执行 VACUUM。

清理使用存储租约，覆盖数据库事务及附件回收；未提交的 config_save 恢复日志阻止数据库访问。附件只删除 images 普通目录中 64 位小写十六进制 SHA-256 `.png` 普通文件，跳过软链接、任意用户文件名及仍被引用的文件。孤儿扫描重试之前 unlink 失败的文件。仅删除 clipboard_records，不改网页目录或 usage。

验证使用临时 SQLite、模拟 UTC 时间及可控通道等待，不启动系统剪贴板：空闲调度自动清理、边界日和 0、持续队列不饿死维护、256 条批次、条数和 UTF-8 字节上限、文件引用统计、受管附件/孤儿/软链接、迁移后路径隔离、其他表保留、恢复日志阻止清理。已有 writer 排空、迁移租约、config_save 故障恢复测试一并运行。

局限：删除条数有界，但窗口查询与孤儿目录扫描仍与历史规模相关；尚未做超大库耗时基准。容量为周期性最终约束，写入后可暂时超限。未做真实剪贴板、原生窗口开关或退出的手工端到端验证。进程强杀不保证排空队列；正常退出请求会等待在途清理/写入结束。
