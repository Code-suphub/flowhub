## 后续优化和已知边界

1. 频繁刷新会重复发起端口子进程或 IP 网络请求；旧响应有版本防护，但没有统一取消/请求合并。可补并发限制和取消机制。端口信息当前每个 PID 顺序执行三次 ps，进程较多时可以批量读取。
2. 公网 IP 两个地址族分别超时并显示错误，但目前依赖单一服务商，没有备用提供者。代理可能改变结果；查询失败不代表系统没有 IPv6。
3. 结束进程前重新检查 PID、启动时间等身份，但检查与发送信号之间仍有很小的竞态窗口；普通 macOS PID 信号调用不具备原子身份保证。只发送 SIGTERM，不提权，结果可能受权限限制或进程忽略信号。
4. 端口空结果只表示未发现当前用户可见的 TCP 监听/UDP 绑定，不能保证机器上绝对无人占用。
5. 使用 FlowHub Local Development 证书，流程没有 Developer ID 公证步骤。团队已有安装与面向陌生 Mac 的首次安装是不同验证场景，后者仍需实机验证。
