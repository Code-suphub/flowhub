# 全部分页与同步布局修复

## 全部分页

`loadMoreAll` 会调用剪贴板、网页及备忘的真实追加函数，而原 guard 仅接受各自独立范围，导致在“全部”被直接拒绝。现允许 all 或自身范围，仍保留并发加载和末页限制。

新增 `all-native-pagination.test.cjs`，使用真实 refreshClipboard／refreshWeb／refreshMemos 函数验证 all 进入后端、其他范围被拒绝、并发追加被拒绝。原来的整合分页测试只模拟来源函数，未覆盖该 guard。

第一次原生复测已从原来的 301 条提升至 1136 条，100 次有效分页，DOM 结果行最多 77。

## 渲染

新增匹配、HTML、DOM、布局及滚动分段。此前反复出现的 57–62ms render 中，匹配、HTML、DOM、布局计时合计约 1–3ms，剩余时间发生在 render 末尾将 scrollTop 重新赋为原值。即使为 0，这个写入也会使 WebKit 同步计算新 DOM 的布局。

现依靠滚动容器保持原位置；新查询需要回顶部时在 DOM 更新前重置，只有键盘明确定位时才在末尾写入目标位置。避免每次结果刷新都强制一次同步布局。

采样仍不等同于系统呈现跟踪，需对比下一帧等待以免把延迟转移到计时之外。


## 首次预览慢帧的实际定位

去掉滚动写入后同步计时改善，但下一帧仍有 60–78ms，证明仅移除同步刷新不足以解决实际停顿。逐字段布局排除备忘样式；逐行原生布局定位到含 ❌／✅ 的某条剪贴板文本（首次单行布局约 54ms，其他行 0–2ms）。通用字体预热及替换字体栈未稳定消除延迟，均已撤回。

最终折叠预览用轻量 inline SVG 呈现这两个常用状态符号，避免首次彩色字符加载；aria-label 保留原符号，原始字符串、复制、粘贴和展开全文不变。多行预览限制 300 字符／5 个源文本行，CSS 使用块高度裁剪。展开全文仍可能遇到未加载过的其他字形，此改动不是所有 Unicode 字体的通用性能保证。

原生对比：已复现场景同步 render 约 2ms、下一帧等待约 26ms，消除了此前重复出现的 57–78ms 停顿。末页加载 3064 条，四来源 hasMore 均为 false，277 次有效分页、DOM 结果行最多 77。数量来自当时的真实本地数据，可能随剪贴板记录变化。

新增 URL 解析与编解码在该轮修复后实现，详见 `url-tool.md`。没有修改现有 180ms 输入防抖策略。
