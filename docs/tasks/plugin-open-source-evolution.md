# 插件开源借鉴与演进

更新：2026-11-06。主体六项实现、提交和本地签名安装已完成，真实设备待验项目继续留在[安装版验收清单](launcher-desktop-acceptance.md)。下一阶段围绕现有六类插件逐项推进；本文件是实施队列，不表示业务改造已经完成。

## 当前基线

- 插件源码在独立的 `flowhub-plugins` 仓库，主检出位于宿主根目录 `plugins/`，本工作树没有插件检出。业务实现和测试提交到插件仓库；宿主仅在协议或公共宿主能力确有需要时修改。
- 本次核对插件仓库提交为 `657f071`。主检出还有未提交的依赖锁文件、构建和发布脚本调整；这些属于已有工作，不纳入本任务提交。实施前核对要使用的基线，并在独立工作树推进，保留主检出内容。
- 2FA 前端已经 React 化，但后端仍使用手写 Base32／SHA-1 TOTP，只支持 6 位、30 秒；依赖中没有 `totp-rs`，没有 `otpauth://` 导入。
- Docker 已有容器／Compose 分组、镜像、日志、确认操作和桌面组件；机器管理已有连接、工作台、执行记录和监控。先核对具体差距，避免把现有能力重复列为待实现。
- 外设中心已有蓝牙／USB／显示器／供电和电量采集。资源监控沿用已有专项与提交，不在本队列重复重写采集和实例归属。
- 社交聚合当前仍是连接器骨架和演示会话，不能把界面完成视为真实平台接入完成。

上述是基于本地现状的优先级判断，不是对上游代码可直接安装为 FlowHub 插件的承诺。2026-11-06 已重新核对参考仓库的官方 README；具体实施时记录选定版本／提交、模块、许可证和署名要求，分别判断作为依赖接入、移植逻辑或参考交互。

`totp-rs` 明确提供 `otpauth` URL 参数解析；其 `qr` 功能用于生成二维码，不能据此宣称已有图片识别／扫码导入能力。[上游说明](https://github.com/constantoine/totp-rs#features)

## 第一项：2FA 分批交付

- [ ] P1.1：独立工作树和基线记录；使用公开 RFC 测试向量比较现有生成结果，核对依赖 API、版本及打包影响。
- [ ] P1.2：生成器适配。原账户缺省仍按 SHA-1／6 位／30 秒处理，现有加密存储和数据目录保持兼容；新增参数需明确校验，不静默改变旧账户。
- [ ] P1.3：手动粘贴 URI 导入。解析后展示账户、发行方和生成参数；取消不写入，重复账户给出明确选择，保存后列表与启动器搜索可用。错误不得回显含密钥的完整 URI。
- [ ] P1.4：验证、提交和插件安装。只用公开测试密钥和独立数据目录，先完成回归／只读预览，再构建独立插件包并验证宿主加载。

图片识别、摄像头扫码、批量迁移和密钥导出单独拆项；第一批不将它们计为完成。

## 每批验收与交付

- [ ] 实现前记录“当前已有行为 → 本批变化 → 参考模块”，每批有可独立评审的范围。
- [ ] 运行该插件的类型检查、行为／后端测试、自包含构建与资源检查；公共组件改动追加受影响插件回归。
- [ ] 使用隔离数据检查浅色／深色、宽窄窗口、键盘、焦点返回、慢响应、失败重试和草稿保留；浏览器预览保持只读。
- [ ] 真实平台验证只使用明确的测试账户、容器或机器；验证结果与模拟结果分别记录，不把测试指令发向日常业务对象。
- [ ] 在插件仓库提交实现和验证清单；构建、验证并更新对应的本地安装插件。只有宿主能力有变更时才替换宿主，不把插件源码提交误当成已安装版本更新。
- [ ] 留存版本／提交、检查结果和实机待验项；推送、发布标签和正式发布另按用户指令执行。
