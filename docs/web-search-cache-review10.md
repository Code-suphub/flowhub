# 网页搜索缓存验证（review 10）

日期：2026-09-09。只使用合成网页与 mock 配置/IPC，没有连接真实配置或数据库，没有安装或发布。

## 实现与失效边界

- 每份目录快照建立一个索引。第一次非空有效分词查询时预计算标题、目录/备注、URL 字段；首页空查询不计算字段。
- 每次查询只分词一次。只保存最近一个归一化查询的完整排序，limit/offset 在这个排序上切片。换查询替换结果；空查询恢复目录顺序。空间为 O(目录字段大小 + 网页数量)，不随历史查询数增长。
- 保留原来的五层匹配优先级、细分排序、目录遍历稳定顺序、多词 AND、混合文字分词、分页参数规则。公共 `rankWebPages` 仍是无状态调用，适配层显式持有索引。
- 原生保存成功及 `flowhub:config`（包括目录/存储位置切换）替换整个索引；初次 `get_config` 的旧响应不能覆盖已发布的新配置。浏览器预览仍是只读、页面生命周期配置快照，重新加载取得新配置。
- 网页相关性不依赖全部/网页范围或使用频次，因此两者可复用排序。使用频次卡片仍单独读取 `search_usage` 并响应使用事件，不缓存进网页排序。禁用插件每次查询仍检查。
- 浏览器 `listPlugins` 改为读取内部配置快照，避免每次输入为检查 enabled 而深拷贝整份目录；对外 `getConfig` 继续返回副本。

## 合成性能

复现：`node --expose-gc app/scripts/web-search-benchmark.cjs`。基线从提交 `588cdca772c71a0b5cf6e95d5bb262129ad632e0` 读取旧搜索源码，不切换工作区。10,000 条多语言合成网页；10 种查询 × 4 个 offset 的 40 组结果与基线一致。先预热 3 次，冷查询取 15 次、连续查询/翻页取 7 次；下表为 Rust 编译结束后的测量。

| 场景 | 基线中位 / P95 (ms) | 优化中位 / P95 (ms) |
| --- | ---: | ---: |
| 新索引首个查询（包含字段预计算） | 23.850 / 29.101 | 10.075 / 13.414 |
| 10 种连续查询（索引已预热） | 192.661 / 205.985 | 6.157 / 18.873 |
| 同查询连续 10 页（排序已缓存） | 222.120 / 245.925 | 0.001 / 0.002 |

追加 2,000 个不同查询并 GC 后，保留堆差值 -65,984 bytes，未观察到历史查询累积。这是辅助观测，不是严格内存上界证明；边界由单个 lastQuery/lastResults 的实现保证。翻页数字接近计时器精度，只代表数组切片，不代表端到端 UI 延迟；新查询仍扫描全部网页并排序，首查字段计算仍同步，特别大的目录可能产生长任务。

## 隔离浏览器交互

`node app/scripts/web-search-preview.cjs` 启动临时回环服务。服务仅返回合成配置/空原生接口和仓库 UI 静态文件，任何非 GET 请求都拒绝。打开打印地址，点击网页范围，输入 GitHub、按 ArrowDown、滚动分页、切换全部、输入 GitHub 工具 9999、切回网页。

真实 Chromium/Playwright 操作验证：首项为 GitHub 工具 0，ArrowDown 选中工具 1；滚动后有 60 行；精确查询在两个范围都返回工具 9999。交互期间 PerformanceObserver 未记录 >50 ms 长任务；CDP LayoutDuration 累计 13.794 ms，RecalcStyleDuration 10.716 ms，TaskDuration 144.557 ms（包括所有上述操作）。无页面运行异常；首次加载只有测试服务 favicon 404，服务现已为 favicon 返回 204。

未测真实 Tauri WebView/原生 IPC 与用户目录；配置与频次事件用 mock 验证。合成分布、宿主负载和浏览器实现会影响绝对耗时。没有改动 review 序列表及第 11/12 项。
