# 剪贴板漏录排查（2026-09-08）

## 确认的问题与修复

- macOS clipboard-rs 默认每 500ms 检查 changeCount，快速连续复制的中间状态会丢失。改为 100ms；只有 changeCount 变化才读取正文、写库。
- 文件/图片分支原先互斥，声明格式但无法读取时阻止文本采集。改为成功读取有效载荷才停止尝试，保留自复制抑制行为。
- 其他搜索范围收到更新后未标记剪贴板结果过期，切回时可能沿用缓存；重新唤出取消刷新定时器后也没有补查数据库。现在标记过期、清理全部范围分页键，并在唤出时先画缓存再刷新。
- 过期请求的失败不再清空新请求的结果。
- 采集失败与格式回退写入现有可选诊断日志，只含阶段和格式标签，不含正文。

## 边界与后续

缩短轮询明显改善，但不能保证零丢失：并发压力组仍有一次遗漏，其精确阻塞阶段尚未量化。采集回调中包含同步读取、转换及持久化，系统调度和这些操作可能使有效采样间隔超过设定值。若继续治理，应测量回调各阶段并评估将快照采集与写库分离；不能把这次修复描述为所有负载下完全解决。低于轮询间隔的瞬间复制、密码管理器的特殊格式、尚未具体复现的应用仍不在本次保证范围内。

重复内容按类型及哈希合并、更新最近复制时间和次数，是现有去重行为。历史上没有采集到的中间内容无法追溯恢复。
