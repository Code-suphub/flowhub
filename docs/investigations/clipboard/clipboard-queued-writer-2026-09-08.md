# 剪贴板异步持久化验证（2026-09-08）

前置修复及测量提交：f700392。优化安装版本：0.1.8-local.20260908152422。

## 实现

- 采集线程读取、转换和计算哈希后，以非阻塞方式将拥有数据所有权的快照入队。
- 一个后台线程按 FIFO 顺序持久化，成功后再通知界面。关闭再开启采集共用同一写入线程，已采集的数据继续排空。
- 队列最多 64 个等待任务，数据预算 64MiB 包含正在写入的任务。额度随任务释放；满队列、超预算或接收端故障返回错误并记录现有诊断，避免无界内存增长。
- last_seen_at/created_at 使用采集时刻，避免写入等待改变内容的复制时间。
- 成功采集的计时日志也转移到后台线程，正常采集路径不再写磁盘。格式回退、空载荷和错误路径仍使用原诊断方式。
- 保留原有 SQLite 持久化配置、自复制抑制和重复内容合并行为。

## 安装版实测

用 NSPasteboard 写入 UUID 文本，通过实际数据库核对。测试后恢复剪贴板，并精确清理 140 条合成记录。

| 场景 | 复制间隔 | 入库 | 采集 P50 / P95 / 最大 | SQL 最大 |
| --- | --- | --- | --- | --- |
| 普通短文本 | 250ms | 40/40 | 0.559 / 1.238 / 5.652ms | 8.760ms |
| 1MiB 文本 | 500ms | 10/10 | 6.476 / 7.284 / 7.284ms | 10.221ms |
| 并发原生 WebKit 搜索诊断 | 150ms | 60/60 | 0.485 / 1.272 / 1.617ms | 37.489ms |
| 人为持有数据库写锁 1500ms | 150ms | 30/30 | 0.457 / 1.049 / 1.683ms | 1485.132ms |

写锁测试使用独立连接 BEGIN IMMEDIATE 后等待 1.5 秒再 rollback，不修改任何业务数据。SQL 实际阻塞约 1485ms，排队等待最大约 1283ms，采集仍继续；因此这组测试直接验证写库阻塞已与采集分离。

之前普通短文本为 37/40，采集最大 654ms。但两轮机器负载不一致，不能将普通 SQL 时延变小全部归因于本次改动；本次目标是避免同步写库阻塞采集，写锁测试是更直接的证据。

## 计时定义

clipboard_capture_timing 表示快照读取到提交队列前生成报告的耗时，不含真正持久化、轮询等待、极短的 try_send 操作。成功结果是 queued，不能当成已存盘。
clipboard_persistence_timing 的 totalMs 表示后台持久化及通知耗时，不含 queueWait；queueWait 单独统计。stored 才代表写入成功。

46 项 Rust 测试通过，新增覆盖停滞消费者时入队、FIFO、满队列/断连后的额度释放、在途预算、内存上限及整数溢出。本轮未改动前端。

## 剩余边界

队列是内存队列，进程崩溃或强制退出可能丢失尚未写入的任务；积压超容量会拒绝新任务并记录失败。100ms 轮询和同步读取/图片转换仍可能遗漏极快变化。这次 140/140 只代表所测场景，不保证任意速度或任意负载零遗漏。普通诊断由现有开关控制，不记录正文、路径和哈希。
