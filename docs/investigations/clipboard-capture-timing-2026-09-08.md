## 测量定义与结论

- context / has* / read* / encodePng / hash：剪贴板上下文、格式检查、数据读取、PNG 转换和哈希阶段。
- dbOpen：创建连接；dbExecute：整个 SQLite execute，包括可能的锁等待、语句执行与自动事务提交。没有拆开 fsync 与锁等待，不能断言某一个是已确认根因。
- total：从回调内开始采集到通知发送结束，不含轮询等待以及该条计时日志自身写入。阶段中位数、P95 不可直接相加。
- writeToDbStartMs：测试进程写入剪贴板完成到数据库记录的 last_seen_at；后者在写 SQL 之前生成，所以这不是最终持久化延迟。
- 100ms 轮询在上次回调返回后再等待；同步 SQL 的 624ms 慢样本会明显延长下一次采集间隔。此前只缩短轮询不能解决这一阻塞。
- 数据库持久化 journal_mode 实测为 DELETE。是否切换 WAL、是否复用连接，需要独立验证；这次没有修改事务持久化策略。
- 这次明确定位到 SQL 写入阶段存在长尾；搜索压力组反而更快，表明不能将漏录简单归因于搜索。

后续优先将快照读取与写库解耦，使用单写入线程、有界队列和明确的积压/失败诊断；另行测量锁等待、提交开销。大文本读取本身也有慢样本，解耦写库仍不能保证任意速度复制都不遗漏。
