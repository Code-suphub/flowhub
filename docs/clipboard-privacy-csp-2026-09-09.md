# Clipboard privacy and desktop CSP

Review item 12; implementation based on the already integrated items 01–11.

## Capture controls

The clipboard settings panel exposes pause/resume and sensitive-marker protection, applied on **Save**. Selective application exclusion is **not implemented** and has no editable list or add action:

| Setting under `plugins.clipboard.settings` | Default | Effect |
| --- | --- | --- |
| `capturePaused` | `false` | Stop accepting new records; leave the plugin enabled so history search and paste remain available. |
| `protectSensitive` | `true` | Skip a whole clipboard snapshot when a recognized concealed, transient or generated marker is present. |
| `excludedApps` (legacy/imported only) | `[]` | Backend compatibility guard; not an available selective-filtering feature. Nonempty or malformed imported values conservatively block capture. |

The UI labels unsaved policy changes and says to wait for a successful save before copying sensitive content. A saved policy label is not a claim of verified runtime health; existing integration failures remain visible in the save result. These settings participate in item 08's `IntegrationPlan`. Invalid non-array/non-string exclusion configuration fails closed.

On macOS, read advertised NSPasteboard types **before** reading text, images or file paths. Recognized types are `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`, `com.agilebits.onepassword`, `de.petermaurer.TransientPasteboardType`, `com.typeit4me.clipping`, and `Pasteboard generator type`. Failure to read metadata skips capture while protection is enabled. These are cooperating application markers, not OS-certified secret classification. Unmarked passwords, tokens and keys can still be captured. There is no regex/entropy heuristic advertised as reliable secret detection. See the [NSPasteboard marker conventions](https://github.com/NSPasteboard/NSPasteboard.org/blob/main/index.md).

**Selective application exclusion remains unimplemented.** The current public API integration cannot authenticate the application that wrote a clipboard snapshot. The foreground application is not necessarily the writer; `org.nspasteboard.source` is self-reported and informational. The UI explicitly says the capability is unavailable and directs users to pause before copying sensitive content. It does not allow creating or editing an application list.

If an old config or JSON import contains exclusions, the backend still blocks **all** new captures rather than silently ignoring the policy. A conditional warning explains this and provides **清空旧列表并保存**. That action clears the old value and saves the current draft (including other pending changes, as stated beside the button); it never clears `capturePaused`. Failed saves retain the recovery warning. In-flight saves, reloads and unresolved storage-save conflicts block the action. A future platform implementation needs reliable writer identity and snapshot association before selective filtering can be offered as a completed capability.

macOS `changeCount` identifies the snapshot used at policy application and before payload reading. The writer checks it again before enqueue. A changed version causes the payload to be dropped. The resume baseline is never captured, even if a delayed watcher callback arrives; only a later change is eligible. Repeated changes within the 100 ms polling interval can be missed. This cannot make an application that mutates contents without the expected ownership/version protocol trustworthy. [Apple describes changeCount as an ownership change counter](https://developer.apple.com/documentation/appkit/nspasteboard/changecount).

Other platforms currently have no implemented snapshot-version adapter and therefore do not capture. They must not claim equivalent marker/source protection. This project targets macOS.

## Queue, storage and lifetime boundaries

Capture authorization and persistence share a mutex and a policy generation. Each writer tags jobs with its generation. Policy application first waits for an already authorized in-flight read/write, changes generation, then stops/joins the watcher and drains/discards stale queued jobs. After save application completes, no pre-transition job can be written, including after resume. Dropped jobs release the existing queue byte reservation. Restarting for other clipboard settings also discards older queued jobs; this intentionally prefers privacy over retaining every pending record.

An in-flight write can finish **before** pause takes effect. Pause is not retroactive erasure. Combined storage migration still drains the old writer before storage locking, as in items 01/06; the new policy is applied after the configuration transaction commits and before save acknowledgement. Migration/recovery journals and managed-image deletion rules are unchanged.

Lock order is privacy → storage for persistence. Applying policy releases privacy before watcher/writer joins. Storage migration joins before obtaining storage locks. Retention maintenance bypasses capture authorization: while the plugin is enabled, pausing capture continues item 06's minute-based retention/capacity cleanup. Disabling the entire plugin retains its previous behavior, including stopping maintenance and hiding it from search.

History remains ordinary local SQLite/PNG data, not encrypted or scrubbed. Pause/protection do not remove previous secrets, SQLite remnants, backups or copies left by migration. Normal deletion/retention is not secure erase. Clipboard contents already held by the OS or other applications are outside this feature. Dropping queued allocations is not guaranteed memory zeroization. File entries record paths; source files are not deleted by cleanup.

## Desktop CSP

`tauri.conf.json` now has separate production `csp` and `devCsp` policies:

- Scripts: self only, with Tauri's script hash/nonce handling retained; no inline script or eval permission.
- Styles: self plus inline styles, needed by existing HTML styles, tree indentation, virtual list spacers and dynamic UI style attributes. **Only** Tauri's `style-src` injection is disabled via `dangerousDisableAssetCspModification: ["style-src"]`. Otherwise adding a style nonce makes `unsafe-inline` ineffective and breaks those attributes. Script modification remains enabled.
- Images: self, data URLs (managed clipboard PNGs/native icons), and HTTPS. HTTPS image origins are intentionally unrestricted because user-configured website icons accept arbitrary HTTPS URLs. This permits requests to icon hosts and is a remaining privacy boundary; HTTP icons are blocked. No file/asset protocol permission is added because current managed assets are delivered as data URLs.
- Connections: self, Tauri IPC (`ipc:`, `http://ipc.localhost`, `https://ipc.localhost`), Google DNS, ipwho.is, ipapi.co, api4/api6.ipify.org and 4/6.ident.me. No generic HTTPS connection source or wildcard.
- Objects, frames, base URLs and form submission are blocked. Fonts stay local/system.
- Development additionally permits only `ws://127.0.0.1:5174` for the configured Vite HMR port. Production does not permit that socket. The ordinary external browser preview is separate from Tauri's CSP injection.

Cloudflare inspection now invokes a native command. It accepts a domain only, rejects literal IPs/local suffixes/credentials/ports/paths, uses HTTPS with a 3-second connect/6-second total timeout, disables redirects and reads only response headers. No shell is involved. DNS can still resolve an accepted domain to a private address; validation is not a network isolation guarantee. CSP governs WebView requests, not authorized native diagnostics or updater requests. Server headers provide Cloudflare evidence, not proof. Fixed DNS/IP services and custom icon hosts still receive requests when used.

## Verification

All tests use synthetic records, temporary storage fixtures or stub IPC; no real clipboard, user config or user database is accessed. No app installation, signing, publishing or real app launch was performed.

- `CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 CARGO_INCREMENTAL=0 npm test`: 91 Rust tests plus the full UI and read-only preview suites. New tests cover marker defaults/opt-out, pause/resume baselines, unsupported/malformed exclusions, IntegrationPlan changes and a blocked in-flight write with a stale queued image, verifying that existing history survives and reservations are released.
- `... npm run test:security` is now included by `npm test` (and thus the existing release workflow): JS policy/IPC assertions and the real Tauri production `generate_context!`/embedded-assets test (`custom-protocol`), without starting a WebView or app. Confirms production assets exist, fixture code is excluded and style nonce injection stays disabled. It also checks syntax of all three isolated browser fixture scripts and verifies the removed editor is absent.
- `... node_modules/.bin/tauri build --no-bundle --ci`: production compilation and asset generation; no bundle/install/update signing step.
- Isolated browser fixture: `node app/scripts/privacy-ui/serve.mjs`, open settings/search on `127.0.0.1:8767`, select the clipboard settings module, then click **Run isolated privacy checks**. The server serves the actual pages and production CSP with only synthetic IPC responses, including an imported legacy exclusion. Settings save/pause/resume, absent exclusion editor, legacy recovery that preserves explicit pause, search input/keyboard rendering, data images, inline-script/eval denial and blocked unlisted connections pass with no unexpected JavaScript errors. Browser interaction remains a separately executed manual/CUA check, not an unattended part of `npm test`; its scripts receive automatic syntax checks. All standalone `*.test.cjs`/`*.test.mjs` scripts are now reachable from `npm test`.
- `git diff --check`.

The isolated browser is not WKWebView. Live macOS clipboard marker handling and a launched Tauri IPC session were deliberately not exercised under the no-real-clipboard/config constraint. Production code generation/compilation and the pinned Tauri CSP modification path were checked; final live smoke testing must use an explicitly isolated app/data environment.
