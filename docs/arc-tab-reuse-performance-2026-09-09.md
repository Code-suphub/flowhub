# Arc 标签页复用性能优化（2026-09-09）

前置功能提交 f712eb5。优化安装版本 0.1.8-local.20260908160214。本机配置保持开启。

## 修改

- 打开网页只读取 core.reuseBrowserTabs 配置，不再为了这个开关读数据库、组装完整网页目录。
- 最多 32 个 URL 定位提示，60 秒有效，内存保存。单 URL 超过 8KiB 不缓存，不改变其打开行为。
- 提示由窗口 ID 和标签 ID 组成，每次使用都检查实际 URL 和隐私窗口标记；已跳转或已关闭则回退查找，不信任缓存内容。
- 无提示时先检查当前标签页，再按原逻辑遍历普通窗口的 Spaces。
- 新建后先检查末尾标签，未定位到时只做一次批量 URL 查找，避免每 50ms 遍历整个集合。
- 不引入常驻轮询。默认浏览器仍每次按系统查询，配置仍实时读取。

## 安装版验证

每次先切到测试页面 B，再让安装版 FlowHub 打开 A；Arc 当时约 500 个标签。测试只访问本机 HTTP 服务器。

优化前 4 次实际调用：274、168、174、164ms。
优化后首轮实际调用：363ms（scan）；随后缓存命中 321、893、523、614、171ms。全部复用成功、数量仍为 1，但两轮结果波动大，不能据此声称整体打开延迟稳定降低。

随后进行 4 轮交替脚本对照，每轮交替/反转顺序，仍先切 B 再选 A，使用相同真实 Arc 状态与同一目标标签：

| 路径 | 4 次耗时（ms） | 中位数 |
| --- | --- | --- |
| 旧完整查找脚本 | 392.04 / 219.12 / 439.52 / 192.91 | 305.58ms |
| 新脚本并传入已核实 ID 提示 | 206.95 / 205.95 / 229.76 / 208.02 | 207.49ms |
| 同一新脚本预编译实验 | 460.57 / 220.00 / 198.55 / 199.74 | 209.87ms |

该对照中提示路径脚本中位数减少约 32%，但样本仅 4 次，且不含 FlowHub 配置读取/默认浏览器查询等外围开销。预编译没有进一步收益，未加入产品。

## 缓存正确性

实际安装版验证：将已缓存标签页 A 导航到另一路径后再打开 A，创建新 A 并选中，没有选中旧标签（773ms）；关闭缓存中的新 A 后再打开，重新创建并选中，A 数量仍为 1（976ms）。

48 项 Rust 测试通过，包含容量上限、过期、使用前取出旧提示、超长 URL 跳过缓存；AppleScript 实际执行验证了 ID 引用和输出解析。未改动前端。

## 边界

真实运行仍受 osascript 启动、Apple Events、Arc 和系统调度影响，不能保证每次低于 200ms。缓存过期或失效仍需要完整查找；新建页面需等待 Arc 异步发布。日志只增加 configMs/browserMs/lookup 等数值或固定标签，不包含 URL/标签 ID。

脚本计时、实际应用计时口径不同；新 elapsedMs 包含锁等待、配置读取等，browserMs 单独覆盖浏览器路径，旧 elapsedMs 未包含配置读取，不能将其直接当作同口径统计。
