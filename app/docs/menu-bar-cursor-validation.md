# 菜单栏显隐：光标与闪现优化验证

## 2026-09-06 验收口径调整

用户明确允许合成输入；目标是保留逐项显隐，同时避免可见光标跳动、抢占用户鼠标和无关隐藏图标闪现。不再以删除逐项能力来满足“零输入”。隔离工作树中的零输入候选不作为本轮实现基线。

本轮回到保留功能的主检出：补充位置检查主线程回调内的移动状态复检，避免后台检查排队后，在图标移动期间继续修复／重建分界。此修正消除一条竞态路径，不证明所有闪现都由它引起。

补充输入启动保护：每轮合成移动前读取 HID 按钮和活动状态；按钮按住立即拒绝，近期活动最多等待 300ms，每 20ms 检查，静止 200ms 后才能执行。达到预算或异常读数时拒绝，不后台排队；等待成功后重新采集光标位置。新增 `menu_bar_item_move_preflight_rejected` 日志，记录原因、等待时间及本轮未投递事件／未操作光标；成功路径也记录预检信息。只保护开始阶段，执行期间的物理鼠标活动和最终恢复旧位置之间的竞争仍未解决。

本轮 14 项 Rust 测试通过，另通过 npm test 的 JS 语法检查及面板脚本语法检查。未安装或启动本轮代码，尚无新版本实机结论。

### 严格光标不受控实验（2026-09-06）

用户进一步明确要求不移动真实光标、不干扰操作。现有 CursorMoveGuard 的 hide/warp/show 不符合这一条件；启动前静止保护也不能解决执行中用户移动后被拉回的问题。

新增独立 `scripts/probe-menu-bar-pid.swift`，只创建并移除自己的两个 NSStatusItem，向自身 PID 投递 Command mouse-down / mouse-up，不向 Session 投递，不操作真实光标，不更改已有图标或偏好。默认只查权限，显式 `--self-test` 才实验。明确放行本地输入；这不是一个产品适配器。

本机 macOS 15.5、SDK 15.4，权限预检均为 true。首轮测试状态项位于屏幕外（其中 item x=-4386），未重排；同时硬件鼠标移动计数变化，因此采样的光标变化不能归因于合成事件，也不能声称不动光标。首轮大体积报告输出不完整、停止 run loop 未退出，随后终止了本次自有测试进程；测试状态项已移除。探针改为简短摘要并明确退出，详细样本仅 `--samples` 输出。

加入可见性和鼠标活动前置检查后再次运行，返回 `test-items-offscreen; no-events-posted`、sampleCount=0，前台 PID 未变化，进程正常结束。此结果是安全中止，不是显隐成功证据。没有安装／替换 FlowHub，没有测试第三方图标，没有录屏的逐帧闪现证据。继续有效实机实验需要先为两个测试状态项提供可见空间；不暗中展开或停用用户现有隐藏分区。

SDK 与官方文档没有为 CGEventPostToPid 提供全局光标不动的明确保证。Private event source 是独立状态表，不是独立光标；事件过滤控制真实输入是否放行，不隔离光标。不能仅凭选用 PID-only 就标记达标。

## 本轮修改

- 单图标移动不再展开普通隐藏分界和始终隐藏分界，避免主动露出整个隐藏区。
- 在 Session 事件监听点确认事件到达后，再向图标所属进程投递，避免异步投递竞争。
- 按下事件使用桌面外的起点和明确的窗口目标，避免负坐标落到 Apple 菜单。
- 移动期间短暂隐藏光标；同步恢复位置后再显示。不再用异步 MouseMoved 事件恢复位置。
- 恢复光标后被动等待分界动画结束，避免已移动成功却被误判失败、反复拖动。
- 事件超时会补发释放事件；作用域退出时恢复光标。不使用输入锁定或鼠标与光标解绑。

## 仍需区分的限制

这不是完全不操作鼠标的原生显隐接口：底层仍发送模拟事件，光标位置在短暂隐藏期间会改变再恢复。本轮优化的是可见跳动、整区展开和重复拖动。

静态截图和前后窗口记录不能证明每一帧都没有闪现；本轮未完成高速录屏验证，也未覆盖多显示器、持续移动鼠标时的并发操作和整体收起状态的完整回归。不能把以上结果表述为“彻底零闪现、零鼠标操作”。
