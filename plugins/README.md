# FlowHub 插件仓库

> 历史归档：下文描述旧 schema 1 声明式包，已不作为当前安装方式。机器插件已迁到同级独立仓库 `flowhub-machines-plugin`。当前宿主协议与本地目录安装见 [独立插件协议](../docs/plugin-runtime.md)。此目录仅保留旧包及签名工具供历史兼容参考。

此目录可以整体复制为独立的 `flowhub-plugins` 公共 Git 仓库。当前提供 `machines` 声明式能力包：权限清单和命令模板。SSH 执行器、Linux 采集器和 UI 属于 FlowHub 宿主，不能随下载包替换；以后新增宿主能力仍需要升级 FlowHub。

## 本地安装

插件市场默认打开「发现」Tab，用于搜索、安装和管理插件；「来源」Tab 用于配置本地目录和线上仓库。两者分别展示，切换不丢失当前输入。

机器管理分为「机器」「SSH 发现」「远程命令」「执行记录」四个 Tab，默认显示机器列表和监控概况。SSH 配置发现仍在打开页面时自动进行，结果在「SSH 发现」中查看。勾选机器后可前往远程命令，切换时保留选择和草稿；新增和编辑机器的表单仍由按钮展开。

SSH 发现只展示未纳管主机，支持配置来源和关键词筛选。远程命令页可直接使用搜索多选下拉框选择目标，无需返回机器 Tab，选择与机器列表同步。执行记录只显示远程命令，支持按实例 ID 和状态过滤，已删除实例的历史记录仍可筛选。指标采集记录在“机器”列表每台机器的“采集记录”中查看。两类记录各保留最近 100 条，后台采集不会挤掉命令历史；记录仍仅存在内存中。

运行支持机器管理的 FlowHub 构建，在「设置 → 插件市场」新建本地来源并选择本仓库的 `plugins` 目录，扫描后找到机器管理并安装；也可选择单个 `machines/package.json` 文件安装。未配置来源时不自动展示随附包。安装并启用后，侧栏自动出现「机器管理」，直接在当前设置窗口内使用。停用或卸载后隐藏机器入口，插件市场入口一直保留。机器配置页面不包含安装或仓库设置。不需要公共仓库，也不需要在服务器安装 Agent。

添加机器时填写本机 `~/.ssh/config` 的 Host 别名。先在终端完成首次主机指纹核对和密钥认证，然后手动采集。SSH 配置中的跳板机由系统 OpenSSH 处理。密码登录可使用「终端」按钮；后台采集和命令面板使用 BatchMode，不会弹出密码输入框。

机器页面启用后自动显示「本机 SSH 发现」：扫描 `~/.ssh/config` 与 Include 文件（支持相对路径、绝对路径、`~/`、通配路径和带空格的引号路径），展示别名、来源文件及行号、扫描结果和读取提示。循环文件只读一次；最多 16 层、128 个文件、4 MiB、500 个别名。通配 Host 不生成机器，Host/Match 条件条目作为候选展示，不在发现阶段求值或运行命令。

点击候选别名，通过系统 `ssh -G` 查看实际生效的地址、用户、端口、跳板机及候选私钥路径。勾选后「加入管理」才保存机器，已有别名不会重复添加。「测试连接」由用户触发，沿用完整 SSH 配置，不把展示字段作为额外覆盖参数。发现阶段不建立 SSH 连接，也不自动开启监控；修改配置后可重新扫描。

## 图形化 SSH 配置与连接测试

在「添加机器 / 编辑」中填写别名，点击「从本机配置填入」可读取已有 SSH 配置。也可以直接沿用本机配置，或填写自定义连接信息；私钥选择按钮位于路径右侧。底部统一点击“保存”。分组支持选择已有分组或新建。私钥只保存路径，不复制内容；页面暂不支持密码认证，带口令私钥仍需通过 ssh-agent 解锁。

界面生成 `~/.ssh/flowhub.d/<别名>.conf`，首次保存会在 `~/.ssh/config` 顶部加入 `Include flowhub.d/*.conf` 和 `Host *` 恢复段，并备份原主配置。原内容保持不变；这里的普通字段优先于原有同名条目。IdentityFile 是可累计配置，选择新密钥不会移除原配置中的候选密钥，留空表示继承。新增文件权限为 600，管理目录为 700。检测到文件外部变化、手动修改受管文件或符号链接时，不自动覆盖。

「测试连接（当前表单）」不要求先保存，会用当前字段及本机 SSH 配置建立全新的连接，检查认证与固定命令执行。超时 20 秒；显示认证失败、主机指纹问题、连接拒绝、名称解析失败等信息。首次主机指纹必须先在终端核验，不自动信任。探测不是单纯 Ping，不成功也不一定代表机器离线。

统一保存时，只有连接字段发生修改才写入 SSH 配置，再保存机器清单；SSH 写入失败时保留表单，不保存清单。若 SSH 已写入但清单保存失败，会明确提示重试。删除机器清单项不会删除 SSH 配置。写入需要插件声明 `ssh:configure` 权限。列表“命令”选中该机器并进入工作台，“系统终端”打开外部交互式 SSH，可按服务器要求输入密码。本功能测试使用模拟适配器和临时目录。

## 本地开发流程

### 堡垒机交互会话

机器表单选择“堡垒机交互会话”，填写目标机器名称、本地可执行 relay 脚本的绝对路径，以及连接指令（例如 `n`）。这些字段保存在 `~/Library/Application Support/FlowHub/machines/state.json` 的机器 `bastion` 配置中，不写入 OpenSSH 配置，也不复制脚本、密码或验证码。

本机需要 tmux。点击该机器的“命令”，在工作台点击“连接会话”启动脚本。识别 `user@host ->` 提示符后自动发送一次目标指令；不认识的登录提示可以通过输入框处理。页面提供最近约 200 行终端输出、逐行输入、隐藏输入、回车及 Ctrl+C，不是完整的终端模拟器。全屏程序、复杂键盘操作使用“在系统终端附着”，它连接到同一个 tmux 会话，保留目标机登录状态和目录。任意一端输入都会影响同一会话。

关闭页面或应用不会终止 tmux 会话，重新选择机器可恢复查看。断开会话会终止其中程序及附着终端；断线不自动重连或重放命令。运行中的会话需先断开，才能修改堡垒机连接配置或删除机器。堡垒机暂不支持自动指标采集，交互内容不进入逐条命令执行记录。tmux 使用独立 FlowHub socket，不读取个人 tmux 配置；会话及滚屏由本机 tmux 进程维护，不将登录状态序列化到 JSON，电脑重启后需重新认证。

独立浏览器预览中的连接、输入和状态都是模拟，不会运行 relay 或打开系统终端。原生实现已使用本地假堡垒机脚本测试；真实 relay 的登录和平台会话限制仍需开发版联调。

命令工作台可配置“每次独立连接”或“复用已认证连接”，并设置空闲保留 1 分钟至 1 小时。配置保存到本机，适用于后续命令、指标采集及系统终端；独立模式显式关闭 OpenSSH 复用。复用使用 `~/.ssh/flowhub-connections/%C` 的私有套接字目录（700），首次密码/验证码认证需通过系统终端完成；不保存密码，后台任务仍使用 BatchMode。切换独立模式不终止已有终端或主连接，既有主连接按建立时的空闲超时退出；电脑重启、连接断开后需重新认证。共享 SSH 连接不共享 Shell 的目录和环境变量。

Expect 等跳板机脚本需要在首次 SSH 建连时使用相同的复用参数，且服务器必须允许多会话。跳板机内部再通过交互命令登录目标机，属于另一层 Shell 状态，无法通过外层 ControlMaster 自动继承；应根据跳板平台支持的目标连接命令或 ProxyJump 能力单独适配。FlowHub 不自动执行外部登录脚本。

远程命令采用工作台布局：本页提交的命令直接显示每台机器的状态、标准输出、错误和退出码，保留最近 100 条。支持原位取消、清空已完成输出，以及 Cmd/Ctrl + Enter 执行（Enter 换行）；清空不删除会话执行记录。当前仍是独立 SSH 命令任务，输出在任务结束后返回，不提供交互式 PTY 或跨命令的工作目录、环境变量持久化。

远程命令页提供“管理模板”，可新建、编辑、删除模板。第一次编辑以插件模板为初始内容，保存后作为本机独立模板列表；清空全部模板后隐藏选择入口，但仍可通过“管理模板”新建。桌面版写入 `machines/state.json` 的 `templates` 字段，插件更新不会覆盖本机模板。独立预览仅在内存保存，刷新重置。模板只填入命令，执行仍由“执行命令”按钮触发。

### 独立页面调试（无需安装 FlowHub）

在 FlowHub 主项目执行：

```sh
cd app
npm run dev:machines
```

浏览器打开 `http://127.0.0.1:5183/machines.html`。预览复用正式页面源码，修改 HTML、CSS、JS 自动刷新；顶部明确标记模拟模式，可切换成功、失败、超时，重置恢复初始数据。支持机器增删、SSH 发现和纳管、模拟配置与连通测试、采集、命令提交、取消及记录过滤。任意输入的命令只作为文本展示，执行结果约 3 秒后返回。后台监控开关只生成一次模拟指标快照，不进行周期采集。

模拟数据仅存在页面内存，刷新后重置。独立服务没有本机配置、私钥、终端或 SSH 接口。开发适配器位于 `app/dev/`，由独立 Vite 配置注入，不包含在正式应用页面中；普通 `dev:web` 仍为只读预览。这里验证的是交互，不是真实 SSH。

需要验证真实 SSH 时，退出已安装 FlowHub，在 `app` 运行 `FLOWHUB_TAURI_SHOW_SETTINGS_ON_START=1 npm run dev`。该开发版仍使用本机数据，页面修改自动刷新，Rust 修改需要重新编译；不需要打包安装。最终验收再执行 `npm run build:local:install`。

### 声明式插件包调试

1. 编辑 `machines/package.json`。在主项目中，对应路径为 `plugins/machines/package.json`。
2. 在桌面版「设置 → 插件市场」添加本地文件夹，选择 `plugins` 或开发包目录；也可使用「安装本地文件」选择单个 JSON 包。
3. 市场扫描根目录及两层子目录中的 JSON 包，支持名称、来源检索和已安装/可更新筛选。查看版本、权限和完整命令模板，点击「确认安装」。本地测试不需要签名或联网，审阅页明确标为未验签。
4. 打开市场自动扫描，停留期间每 30 秒检测目录变化，也可以手动刷新。修改文件后点击「审阅更新」再次安装。同版本允许覆盖，无需重启 FlowHub；使用的是审阅时的文件快照，不会悄悄加载审阅后发生的修改。扫描跳过符号链接、隐藏目录、node_modules 和 target，最多 16 个来源目录和 2000 个目录项。
5. 安装保留机器清单，可通过「回退上一版」撤销。安装时取消当前任务并关闭后台监控，之后可手动测试或重新开启监控。源文件删除/格式错误/权限不支持时保留当前已安装版本。
6. 测试通过后更新发布版本号，按下方流程签名、打包并发布到公共仓库。远程安装不会因为支持本地开发而放宽签名要求。

当前测试的是声明式 JSON 包（权限和命令模板），不是任意 JS、Rust 或 UI 插件的热加载。修改宿主 SSH 服务或界面源码仍需要重新构建/启动开发版。浏览器预览不能安装本地文件。

在市场「来源列表」中可配置多个线上仓库和本地目录，分别最多 16 个。默认展示列表或“暂无来源”，点击新建才展开配置，保存或取消后收起。线上仓库各自保存 HTTPS 目录地址和可信发布公钥，支持编辑、单独刷新和移除；本地目录支持更换、单独扫描和移除。旧单仓库配置自动兼容并在编辑时迁移。保存来源、打开市场或手动刷新时检索并验签，一个仓库失败不阻止其他仓库检查，列表分别显示结果。未配置来源时禁用「刷新全部来源」，待安装列表不会自动加入随附插件；已安装插件仍保留管理入口。扫描只发现版本，不自动安装更新；移除来源不卸载已经安装的插件。

## 发布公共仓库

以下步骤供仓库维护者使用，**当前没有创建远程仓库或发布版本**。命令从独立插件仓库根目录执行。

1. 修改 `machines/package.json` 中的版本、宿主兼容范围和模板。
2. 使用 [Minisign](https://jedisct1.github.io/minisign/) 生成专用插件签名密钥，保存在仓库外。不要复用 FlowHub 应用更新密钥。

```sh
minisign -G -p ./machines.pub -s ~/.minisign/flowhub-plugins.key
minisign -Sm machines/package.json -s ~/.minisign/flowhub-plugins.key
minisign -Vm machines/package.json -p ./machines.pub
```

3. 按最终下载位置生成目录。示例地址中的 OWNER 和 REPO 需要替换。

```sh
node scripts/package.mjs \
  --base-url https://raw.githubusercontent.com/OWNER/REPO/main/public/ \
  --signature machines/package.json.minisig
```

4. 将 `dist/` 中的文件复制到公共仓库 `public/` 并提交。保留旧的 `packages/machines/<版本>/`，只更新 `registry.json` 指向当前版本。也可放在静态站点或 Release 下载地址；客户端仅允许 HTTPS 下载及最多 5 次 HTTPS 重定向。无需运行 Web 服务。
5. 用下面的命令编码完整公钥文件，并通过独立可信渠道提供给安装者：

```sh
node -e "process.stdout.write(require('node:fs').readFileSync('machines.pub').toString('base64'))"
```

安装者在插件面板填写 `https://raw.githubusercontent.com/OWNER/REPO/main/public/registry.json` 和公钥，点击「保存仓库源 → 检查插件版本 → 安装已验证的版本」。界面展示待安装版本和权限；SHA-256 校验完整性，固定公钥校验发布者签名。

签名只证明来源和完整性；安装者仍需要信任发布者及其命令模板。模板只会填入命令编辑器，不会自动执行。更新由用户点击触发，可以明确安装较旧的已签名版本；不声称具有自动防降级策略。

## 管理与数据边界

- 停用：关闭监控并取消正在运行和排队的 SSH 任务。
- 回退：交换当前版本与上一个已安装版本，并重新检查宿主兼容性。
- 卸载：移除插件和回退版本，保留机器清单与仓库设置。
- 更新失败：保留原安装状态。更新和回退会取消现有任务。
- 本地机器配置：`~/Library/Application Support/FlowHub/machines/state.json`，独立于网页/剪贴板数据库迁移；备份 FlowHub 时一并备份该目录。
- 当前指标和最近 100 条执行记录仅在进程内存中，退出即清空。每条标准输出和标准错误各限制 32 KiB；不做历史趋势存储或告警。
- 支持最多 500 台机器清单，实际采集吞吐量取决于连接时间；每批命令最多 16 台、全局并发最多 4 个。后台以最多 4 台一组轮询，30–3600 秒为每台期望间隔，忙碌时会延后。
- Linux 采集包括 CPU、内存、根目录磁盘、1 分钟负载、运行时间。其他系统可执行命令和打开终端，暂不支持统一指标采集。
- 基础采集超时 20 秒，远程命令超时 60 秒。取消/超时只保证关闭本机 SSH 子进程，不能保证远端命令结束；持续任务请使用终端和远端进程管理工具。
- 导入识别主 `~/.ssh/config` 中明确的 Host 别名，不枚举通配符、Include 或 Match；这些主机可以手动添加别名，连接时 OpenSSH 仍解析完整配置。
- `ssh-agent`、`known_hosts`、密钥和本机 SSH 配置继续由 OpenSSH 管理。不会同步到公共仓库，也不会关闭主机密钥校验。
- 浏览器仅提供只读布局预览，没有 SSH 或配置写入接口。

## 协议

`registry.json`：`schema: 1`，`packages` 中每项包含 `id`、HTTPS `url`、小写 `sha256`、完整 Minisign 签名文件的 `signature`（Base64）。文件和目录大小都限制为 256 KiB。

`machines/package.json` 是签名的原始字节。宿主拒绝未知 manifest 字段、未知插件 ID、额外权限和不兼容版本。接受 `ssh:collect`、`ssh:execute`、`ssh:terminal`、`ssh:configure`。可信公钥由用户保存，不从仓库自动替换。
